# Deploying Homesika to Render

`render.yaml` in the repo root is a **Render Blueprint**: one file that describes every piece
Render must create. Staging is first; production is a copy with live keys, made when you are
ready to launch.

| Render resource | What it runs |
|---|---|
| `homesika-staging-api` (web service, Docker) | Django API + WebSockets (Daphne), at `https://homesika-staging-api.onrender.com` |
| `homesika-staging-worker` (background worker) | Celery: reminders, receipts, reconciliation, provider calls |
| `homesika-staging-beat` (background worker) | Celery beat: the scheduler (always exactly one) |
| `homesika-staging-db` (PostgreSQL 16) | All data |
| `homesika-staging-redis` (Key Value) | Job queues, cache, WebSocket messages |
| `homesika-staging-web` (static site) | The React dashboard |

## One-time setup

1. **Push the repo to GitHub** (`gintason/homesika`).
2. **Create a Render account** at render.com and sign in with GitHub. When asked, give Render
   access to the `homesika` repository only.
3. In Render, choose **New → Blueprint**, pick `gintason/homesika` and branch `main`. Render
   reads `render.yaml` and shows the list of resources above.
   * If it shows an error about a field, copy the message to me. The file is marked
     `TODO(verify)` because Render's docs weren't reachable from my build environment.
4. **Fill in the secrets Render asks for** (those marked `sync: false`):
   * `FIELD_ENCRYPTION_KEYS`: run this on your Mac and paste the output:
     `python3 -c "import os,base64;print(base64.b64encode(os.urandom(32)).decode())"`.
     **Keep a copy in your password manager.** Losing it means encrypted data can't be read.
   * `SENTRY_DSN`: optional now (leave empty), recommended before pilots.
   * `CORS_ALLOWED_ORIGINS` on the API: `https://homesika-staging-web.onrender.com`.
   * `VITE_API_URL` on the web site: `https://homesika-staging-api.onrender.com`.
   * `DJANGO_SECRET_KEY` is generated by Render automatically.
   * `PAYSTACK_SECRET_KEY`, `FLUTTERWAVE_SECRET_KEY`, `FLUTTERWAVE_WEBHOOK_HASH`, `TERMII_API_KEY`:
     leave empty at first. Staging starts with the **mock** gateway and mock SMS (nothing real is
     charged or sent). When you have **test** keys, paste them in Render (never in chat or GitHub),
     then change `PAYMENT_GATEWAYS` to `paystack,flutterwave` in the `homesika-staging-shared` group.
   * Webhook URLs to enter in the gateway dashboards:
     `https://homesika-staging-api.onrender.com/webhooks/payments/paystack/` and
     `.../webhooks/payments/flutterwave/`.
5. Click **Apply**. The first build takes a few minutes. On every deploy, the API runs
   `migrate` before taking traffic.
6. **Check it:** open `https://homesika-staging-api.onrender.com/health/ready`. You should see
   `{"status": "ok", ...}`.
7. **Create your admin user:** open the API service → **Shell**, then run
   `python manage.py createsuperuser`.

## Phase 2: WhatsApp, the assistant and photos

Do these when you're ready; until then staging uses the mock WhatsApp and mock assistant.

1. **Photos (do first; listings need them).** Create a Cloudflare R2 bucket (or S3), make it public
   (or attach a custom domain), and create an API token with read/write access to it. Then set
   `S3_BUCKET`, `S3_ENDPOINT_URL` (R2: `https://<account-id>.r2.cloudflarestorage.com`),
   `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` and `S3_PUBLIC_DOMAIN` (the public bucket domain).
2. **Claude.** In the Anthropic Console, create an API key for a "homesika-staging" workspace and set a
   monthly spend limit there too.
   * Paste the key as `ANTHROPIC_API_KEY` in Render (never in chat or GitHub).
   * Set `ASSISTANT_PROVIDER` to `anthropic`.
   * Run the evaluation once from the API service's **Shell**:
     `python manage.py assistant_eval --limit 10 --yes`, then the full set (it costs money; the
     command shows the estimated cost).
3. **WhatsApp.**
   * In Meta Business Manager, create the WhatsApp Business account and add the Homesika number.
   * In the Meta developer app, add the **webhook**:
     * URL: `https://homesika-staging-api.onrender.com/webhooks/whatsapp/`
     * Verify token: any long random string; put the same value in `WHATSAPP_VERIFY_TOKEN`.
     * Subscribe to the **messages** field.
   * Set these in Render:
     * `WHATSAPP_PHONE_NUMBER_ID`;
     * a permanent `WHATSAPP_ACCESS_TOKEN` (system user token);
     * `WHATSAPP_APP_SECRET` (App settings → Basic);
     * `SUPPORT_PHONE`;
     * `WHATSAPP_PROVIDER` = `cloud`.
   * Submit the templates in `docs/WHATSAPP_TEMPLATES.md`, and list each one in `WHATSAPP_TEMPLATES`
     once approved.

     get started" guide.

## Every later release

Just push to `main`. Render redeploys automatically; CI on GitHub runs the tests in parallel.
To stop broken builds from deploying, you can turn on "deploy only when CI passes" later (Render
calls this *auto-deploy after checks pass*; `TODO(verify)` the exact setting name).

## Good to know

* **Plans and cost:** background workers, Key Value and the always-on web service need paid
  plans. The names in `render.yaml` (`starter`, `basic-256mb`) are placeholders to check against
  your dashboard. See render.com/pricing. Free Postgres instances expire after a limited time,
  so don't use one for real data.
* **Region:** `frankfurt` is set because it's the closest Render region to Nigeria that I know
  of. Change it if Render now offers something closer.
* **Files:** Render's disks are wiped on every deploy, so nothing important is stored on them.
  Receipts are generated on request. Tenant photos and documents (later phases) go to S3-compatible
  object storage (e.g. Cloudflare R2), which we set up when the first upload feature ships.
* **Secrets:** they live only in Render (and your password manager), never in GitHub.
* **Production:** duplicate `render.yaml`'s services with `-prod` names (or use Render's
  environments feature), live provider keys, `config.settings.production` and a custom domain
  (`api.homesika.com`, `app.homesika.com`).

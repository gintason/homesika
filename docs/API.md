# Homesika: API outline

> **The exact contract is `docs/openapi.yaml`**, generated from the code (`python manage.py spectacular
> --file ../docs/openapi.yaml`); CI fails if it is out of date. This page explains the conventions and
> the plan for later phases.

Base path: `/api/v1`. The API is JSON over HTTPS. The OpenAPI schema is generated by
drf-spectacular at `/api/v1/schema/`, with docs at `/api/v1/docs/` (non-production only).

## Conventions

* **Auth:** send `Authorization: Bearer <access JWT>`. Access tokens live about 10 minutes;
  refresh tokens rotate and are blacklisted on use.
* **Org context:** staff endpoints are nested under `/orgs/{org_id}/…`. Membership and role are
  checked on every request, and an object outside the org returns **404** (never 403, so object
  existence doesn't leak).
* **Self-service endpoints** (tenant, resident, artisan) live under `/me/…` and return only
  the caller's own data.
* **Money** goes out as strings in major units (`"150000.00"`) with `currency`. It comes in the
  same way, and is stored as integer kobo.
* **Idempotency:** requests that create money movement or records (`payments/manual`,
  `payment-links`, `me/pay`, `charges`, `expenses`, `settlement-accounts`) accept an
  `Idempotency-Key` header (16–64 characters). A retry with the same key and body returns the
  original response with `Idempotent-Replayed: true`; the same key with another body gets 422;
  a retry while the first is running gets 409. Optional in Phase 1 (our clients always send it);
  it becomes required before third-party API access opens.
* **Errors:** always the same envelope.
  `{"error": {"code": "<stable_code>", "message": "<localised>", "details": {…}}}`
  The language follows `Accept-Language` (`en`, `pcm`, later `fr`).
* **Pagination:** cursor-based (`?cursor=`); default 20 items, maximum 100.
* **Filtering and search:** `?status=`, `?property=`, `?q=` where documented.
* **Rate limits:** per IP and per user scopes; `429` comes with `Retry-After`.
* **Caching:** `ETag` on read-heavy GETs, for weak networks.

## Auth and account [Phase 1]

| Method | Path | Purpose |
|---|---|---|
| POST | `/auth/register/` | Start sign-up (name, phone, email) → OTP challenge |
| POST | `/auth/otp/resend/` | Resend, or switch SMS → email |
| POST | `/auth/otp/verify/` | Verify code → `create_pin` or signed-in |
| POST | `/auth/pin/setup/` | Create 6-digit login PIN, bind device |
| POST | `/auth/pin-login/` | Everyday login: device + PIN |
| POST | `/auth/login/` | New device: phone/email + PIN → OTP |
| POST | `/auth/pin/forgot/` | Reset PIN via OTP (signs out other devices) |
| POST | `/auth/refresh/`, `/auth/logout/` | Token rotation, sign out |
| GET/PATCH | `/me/` | Profile, language |
| POST | `/me/transaction-pin/` | Set/change 4-digit transaction PIN |
| GET/POST | `/me/consents/` | View/grant/withdraw consents |
| POST | `/me/data-requests/` | Export or delete my data (NDPA) |
| GET/POST/DELETE | `/me/devices/`, `/me/push-tokens/` | Device management, push registration |

## Module E: estates and security [Phase 5, built]

Estate office (`estate.view` / `estate.manage`: owner, manager, estate admin; accountants and viewers can view):

| Method | Path | Purpose |
|---|---|---|
| GET, POST, PATCH | `/orgs/{org}/estates/` · `/{id}/` | Estates. POST takes `houses: ["A1", …]`; PATCH sets `panic_enabled`, `alert_residents`, `gate_instructions` |
| GET, POST | `/orgs/{org}/estates/{id}/houses/` | Houses (units of the estate's property); POST `{labels: [...]}` |
| POST | `/orgs/{org}/estates/{id}/regenerate-code/` | New join code |
| GET, POST | `/orgs/{org}/estate-members/?estate=&status=` | Residents; POST adds one already verified |
| POST | `/orgs/{org}/estate-members/{id}/approve/` · `/suspend/` · `/remove/` | Approve (choose the house), suspend, remove |
| GET, POST, PATCH | `/orgs/{org}/dues-plans/?estate=` | Dues (`amount` like `"15000.00"`); creating or changing one raises charges at once |
| GET, POST | `/orgs/{org}/announcements/?estate=` | Announcements (POST: Idempotency-Key; push, SMS for people without the app, or SMS to all if `urgent`) |

Gate (`gate.verify`: security, estate admin, manager, owner):

| Method | Path | Purpose |
|---|---|---|
| POST | `/orgs/{org}/gate/verify/` | `{estate, code}` → the pass (no visitor phone); 404 `gate_pass_invalid` |
| POST | `/orgs/{org}/gate/{id}/check-in/` · `/check-out/` · `/deny/` | Gate events; check-in tells the host |
| GET | `/orgs/{org}/gate/?estate=&status=` | Gate log |

Residents:

| Method | Path | Purpose |
|---|---|---|
| GET | `/me/estates/` | My memberships, with `dues_outstanding` |
| POST | `/me/estates/join/` | `{code, house}` → pending membership |
| GET | `/me/estates/announcements/?estate=` | News for a verified resident |
| GET, POST | `/me/gate-passes/?status=active\|all` | Gate passes (POST: Idempotency-Key; the code is texted to `visitor_phone` if given) |
| POST | `/me/gate-passes/{id}/cancel/` | Cancel a pass |

Panic alerts:

| Method | Path | Purpose |
|---|---|---|
| POST | `/me/alerts/` | **Raise** `{estate, kind, silent, location?, client_id}`. 201 new, 200 the same alert (retry with the same `client_id`, or a second press within 2 minutes). 403 `panic_not_allowed`, 429 `panic_rate_limited` ("call 112") |
| GET | `/me/alerts/` · `/{id}/` | My alerts (status only; no delivery details) |
| POST | `/me/alerts/{id}/kind/` · `/cancel/` | "What's happening?"; "I'm safe" |
| POST | `/me/alerts/{id}/received/` | The app reports that an alert push reached this person (204) |
| GET | `/orgs/{org}/alerts/?status=open\|closed\|all&estate=` · `/{id}/` | Security desk (`security.view`); detail has the incident log, every delivery and timings |
| POST | `/orgs/{org}/alerts/{id}/acknowledge/` · `/respond/` · `/resolve/` · `/false-alarm/` · `/kind/` · `/notes/` | Lifecycle (`security.respond`); resolve and false alarm need a note |
| POST | `/orgs/{org}/alerts/drill/?estate=` | Test alert to staff only (`estate.manage`) |
| GET | `/orgs/{org}/alerts/report/?estate=&days=` | Alerts, drills, false alarms, median time to first delivery |
| WS | `/ws/estates/{id}/desk/` | Live desk. Send `{"type":"auth","token":"<access token>"}` first (not in the URL); then `alert.new` / `alert.updated` messages. Closes 4401 (no auth in 10 s) or 4403 |

Push: `POST` / `DELETE /me/push-devices/` `{token: "ExponentPushToken[…]", platform}`.

## Phase 6: analytics, referrals, airtime abroad, markets [built]

| Method | Path | Purpose |
|---|---|---|
| GET | `/orgs/{org}/analytics/?months=6` | Month by month: billed, collected, collection rate, paid on time, dues; plus today's occupancy, arrears, repairs, leads and alerts (`report.view`) |
| GET | `/platform/metrics/?months=6` | Homesika's own numbers (staff accounts only) |
| GET | `/me/referral/` | My code, share message, free fees left, invited/qualified counts |
| POST | `/me/referral/redeem/` | `{code}`: a new account adds a friend's code (14 days, before a first purchase) |
| POST | `/auth/register/` | Now takes an optional `referral_code` |
| GET | `/bills/intl/countries/` | Countries for airtime abroad (503 `intl_unavailable` when off) |
| POST | `/bills/intl/lookup/` | `{country, phone}` → the number in international format and its network, with naira limits and an fx estimate |
| POST | `/bills/intl/orders/` | `{country, phone, amount}` (Idempotency-Key) → a bill order; then the usual `/bills/orders/{id}/` |
| GET | `/markets/` | Countries and cities switched on, with areas and DisCos (public) |

Bill orders now include `fee_waived` (a free service fee from an invite) and `intl` (country and
network, for airtime abroad).

## Webhooks (no auth header; signature-verified, idempotent)

| Path | Source | Verification |
|---|---|---|
| `/webhooks/paystack/` | Paystack | HMAC signature header, `TODO(verify)` against current docs |
| `/webhooks/flutterwave/` | Flutterwave | Secret hash header, `TODO(verify)` |
| `/webhooks/whatsapp/` (GET verify, POST events) | Meta | Verify-token challenge + payload signature, `TODO(verify)` |
| `/webhooks/vtu/{provider}/` | VTU providers | Per provider, `TODO(verify)` |
| `/webhooks/sms/{provider}/` | SMS delivery reports | Per provider, `TODO(verify)` |

Every webhook is stored first (unique by provider event id), acknowledged fast with a 200, and
processed by Celery. Payments are re-verified with the gateway API before they count.

## Health

* `GET /health/live`: the process is up.
* `GET /health/ready`: the database and Redis are reachable. Returns 503 otherwise.
